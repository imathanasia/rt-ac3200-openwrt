ASUS RT-AC3200 on OpenWrt 25.12 A maintained, pre-configured build for a 2015 Broadcom tri-band router — AP mode, AdGuard Home, Tailscale, stats and USB storage, all baked into the flashable image.

OpenWrt 25.12-SNAPSHOT kernel 6.12.116 bcm53xx / arm Cortex-A9 3× BCM43602 radios 256 MB RAM 128 MB NAND no hardware NAT

Hardware — as verified on the unit

Values read from the running kernel / boot log, not from a spec sheet.

SoC / CPU

Broadcom BCM4709A0, ARMv7 Cortex-A9, 2 cores @ 1 GHz (L2 512 KB, MPCORE GIC)

Memory / Flash

256 MB DDR3, 128 MB NAND (Spansion, 2 KB page, BCH8 ECC), dual-bank UBI

Radios

3× BCM43602 (PCIe): 2× 5 GHz + 1× 2.4 GHz · MACs xx:xx:xx:xx:xx:xx/f4/f8

Ethernet

4× GbE LAN + 1× GbE WAN via BCM53012 switch in the SoC

USB

1× USB 3.0 (xHCI) + 2× USB 2.0 (EHCI/OHCI) — storage, SMB, LTE stick

Serial / recovery

Internal 4-pin 3.3 V TTL header · ASUS CFE recovery web UI at 192.168.1.1

What's baked into the image

Every item below was enabled and validated on the physical router before being baked in.

Wi-Fi

3-radio AP out of the box

AC3200-5G ch36 VHT80 + AC3200-2G ch1 HT20, WPA2-PSK, country PL, bridged to LAN.

DNS

AdGuard Home, pre-configured

DNS on 127.0.0.1:5353, Quad9 DoH upstream, AdGuard filter on. dnsmasq → AdGuard → upstream with automatic fallback.

VPN

Tailscale + WireGuard + OpenVPN

Subnet router for your LAN, kernel WireGuard, OpenVPN client/server.

QoS

SQM / cake

Ready for your line speed (set up in LuCI → SQM).

Stats

LuCI dashboard

collectd RRD graphs (CPU, load, RAM, interfaces, per-radio iwinfo), per-device nlbwmon, vnstat2 totals, wifi history, web terminal.

Storage

USB NAS

ksmbd SMB3 + wsdd2, ext4/NTFS/exFAT auto-mount, SMART, one-command extroot to a USB drive.

Remote

Web terminal + SSH

ttyd in the browser, dropbear SSH, root password set (no blank password).

Ops

Self-updating

Attended Sysupgrade (one-click OpenWrt updates), GUI app store, package manager, NTP.

SIM

USB LTE / 5G stick

MBIM + Option + usb-modeswitch drivers baked in for a USB cellular modem.

Flashing it (no serial console)

The stock ASUS / Merlin web UI rejects third-party images ("Invalid Firmware Upload — certification rule"), so use the recovery path.

1
Get the file. Download openwrt-bcm53xx-generic-asus_rt-ac3200-squashfs.trx (34 MB) and verify sha256sum.
2
Recovery mode. Power off → hold Reset → power on → keep holding until the Power LED blinks slowly (~5–10 s) → release.
3
Send the image. PC: static 192.168.1.10/24, gateway 192.168.1.1, cable to a LAN port. Either the ASUS Firmware Restoration utility, or plain TFTP: curl -T *.trx tftp://192.168.1.1/
4
Wait 5–10 min — it reboots into OpenWrt. First boot brings up both SSIDs with the baked defaults.
Never use 30-30-30 on this board (Broadcom ARM). Keep merlin-fallback/RT-AC3200_384.13_10.trx handy to go back to ASUS firmware via the same recovery procedure.
The ASUS download page that hosts the recovery tool and the stock firmware is linked from the build's own LuCI page (see "In-router project page" below).

How it was built

Plain upstream OpenWrt, no vendor tree — plus the fixes that only appear after you boot the thing.

1
Baseline. OpenWrt 25.12 branch, CONFIG_TARGET_bcm53xx_generic, device profile asus_rt-ac3200 — upstream already supports the board (mainline DTS bcm4709-asus-rt-ac3200.dts, brcmfmac + brcmfmac43602-pcie.bin).
2
Boot it once. Found the real hardware facts from the running unit (3 radios, MACs, NAND geometry, CLM blob missing, LAN had no gateway in AP mode, AdGuard stuck in first-run, blank root password, Wi-Fi defaults disabled).
3
Package the feature set. 315 packages: AdGuard Home, Tailscale, WireGuard, OpenVPN, SQM, collectd+nlbwmon+vnstat2, ksmbd, usb storage, ttyd, ddns/acme, and more.
4
Bake first-boot config as /etc/uci-defaults/ scripts + config files (Wi-Fi, AP mode, AdGuard yaml, root password, collectd/tailscale configs, logd/fstab hygiene) and a /root/usb-overlay.sh helper.
5
Validate on metal — each script executed on the live router, then the squashfs was unpacked out of the final .trx to prove every file is inside the shipped image.
scripts/config/conf --olddefconfig Config.in
make -j$(nproc)
# files/ at the tree root = what gets baked

Honest limitations

Hardware/driver limits, not build problems.

Only UNII-1 on 5 GHz

brcmfmac has no vendor regulatory blob (brcmfmac43602-pcie.clm_blob), so channels 100/149 are refused. The second 5 GHz radio is therefore left off — both would sit on ch36. Your ASUS firmware used ch36 + ch100, so the hardware supports it.

No hardware NAT offload

Broadcom: NAT is CPU-bound, ~600–900 Mbit/s on a gigabit line. About the same ceiling as the ASUS firmware.

AP mode only

brcmfmac FullMAC cannot run station/WDS; AiMesh / AiProtection are ASUS-only.

LuCI 25.12 skins

The classic "argon"-style themes are not maintained for the new LuCI; the built-in theme is what ships.
